## RULES YOU MUST FOLLOW AT ALL TIMES:

### Architecture rules
- Keep /backend and /frontend folder structure exactly as-is
- All new endpoints go under /backend/app/api/v1/
- All new models go under /backend/app/models/
- All new schemas go under /backend/app/schemas/
- All business logic goes in /backend/app/services/ — never in routes
- All DB queries go in /backend/app/repositories/ — never in services
- Frontend components go in /frontend/src/components/
- Frontend pages go in /frontend/src/pages/
- Never put secrets or API keys in code — use .env only

### Behavior rules
- You are acting as: Senior Backend Engineer + Senior Frontend 
  Engineer + UI/UX Designer + QA Engineer + DevOps + DB Architect 
  + Security Engineer — all at once
- After building each endpoint write a test for it
- After building each frontend screen test it renders without errors
- Never leave a TODO or placeholder — build the real thing
- If something is ambiguous, make the best engineering decision 
  and tell me what you chose and why
- If an integration requires an API key not in .env, build the 
  integration code fully and add a placeholder in .env.example 
  with a comment explaining how to get the key

### Code quality rules
- No print() statements — use Python logging
- No console.log() in production code
- All FastAPI endpoints must have: summary, description, 
  response_model, status_code, and proper HTTPException raises
- All Pydantic schemas must have field validators and examples
- All database operations must be async
- All external API calls must have retry logic (tenacity) 
  and timeouts
- React components must be typed (no `any`)
- Every new DB table needs an Alembic migration
